# gov5's chains, as genesis files this node loads

Generated by `n42-gov5-genesis` from gov5's `params/chainspecs/<chain>.json`,
`internal/allocs/<chain>.json` and the genesis block fields in
`internal/genesis_block.go`; each hashes to the genesis hash gov5 records in
`params/config.go`, so the fork digest — the chain's name on the wire — is
the same.

| file | chain id | genesis hash | gov5 genesis block |
|---|---|---|---|
| `mainnet_qmdb_staggered.json` | 94 | `0xa2d2ff5d814552bb9a113b68ad7ed2b824fbb52caed42dbe573068845b57be99` | timestamp 1678174066, difficulty 131072 |
| `qs_epoch_test.json` | 95 | `0xb0ff0c044f867741ab595d2756cc5cfb873cff42c6f2ebb913ac4a73a6ad5271` | timestamp 1678174161, difficulty 0 |

Both carry `shanghaiBlock` 305000 and `cancunBlock` 3935000, which reth
cannot see: before running a node on either chain, regenerate with
`--fork-time shanghai=<timestamp of block 305000> --fork-time cancun=<timestamp of block 3935000>`
(from any node's `eth_getBlockByNumber`), which adds the equivalent
`shanghaiTime` / `cancunTime`. The genesis hash does not change.

```
n42-gov5-genesis --chainspec ../N42-gov5/params/chainspecs/mainnet_qmdb_staggered.json \
  --alloc ../N42-gov5/internal/allocs/mainnet_qmdb_staggered.json \
  --timestamp 1678174066 --difficulty 131072 \
  --fork-time shanghai=<ts> --fork-time cancun=<ts> \
  --expect-hash 0xa2d2ff5d814552bb9a113b68ad7ed2b824fbb52caed42dbe573068845b57be99 \
  --out crates/chainspec/res/genesis/gov5/mainnet_qmdb_staggered.json
```

## Running a local fleet on one of these chains

A fresh fleet cannot replay the production fork schedule: its block timestamps
are genesis + slot x period, so a local chain-94 fleet lives in March 2023,
before Shanghai's block 305000, and gov5's block reward (paid by the Rust side as
withdrawals) would have nowhere to go. The chain's own validator keys are not
here either. `scripts/gov5-local-genesis.py` makes the local form, changing only
`config` so the genesis hash stays the chain's:

```
scripts/gov5-local-genesis.py --chain crates/chainspec/res/genesis/gov5/mainnet_qmdb_staggered.json \
  --validators-from crates/chainspec/res/genesis/n42_devnet.json \
  --fork-time shanghai=+1 --fork-time cancun=+1 --out <dir>/c94-local.json
```

(the devnet's four dev validators; Shanghai and Cancun from block 1 for both
clients, gov5 reading `IsShanghaiAt(num, time)`; Pectra, mobileAnchor and
Glamsterdam stay at the chain's timestamps, beyond the local clock, so headers
carry neither slot nor registry root). Run it with
`DEVNET_GENESIS=<dir>/c94-local.json scripts/devnet-mobileanchor.sh <tag> --gov5`.

The genesis-aware device harness can load those changed fork times. A phone
SDK selecting the built-in `mainnet_qmdb_staggered` preset cannot: that preset
still activates Shanghai/Cancun at the production block heights. Empty blocks
can pass while transaction blocks fail because the replay's block-start reads
differ. For phone tests, use a local genesis with the selected SDK preset's
execution rules. See the [iPhone test record](../../../../../docs/device-test-reports/2026-11-03-mobileverify-v3-ios.md).
