## 修复

| 问题 | 原行为与影响 | 修复 |
| --- | --- | --- |
| 复制签名可阻断真实投票 | 直连、批处理和暂存投票的去重键未包含区块哈希；复制真实签名、篡改哈希并抢先发送，后到的真实投票会被误认为重复，从而不能组成 quorum | 所有三处去重同时纳入区块哈希；回归覆盖 Prepare 与 Commit 两轮、直连重复及 quorum 后暂存 |
| 未知投票者占用批处理空间 | 当前视图的投票与提交投票、已过期的投票可携带不存在的验证者编号，占用待验或暂存空间；暂存上限可挤出真实进度记录 | 在进入队列或暂存前，用投票所属视图的验证者集合检查编号 |
| 伪造投票挤占进度记录 | 暂存限制仅按整个视图实施，同一编号的不同伪造签名可占满空间，随后真实投票被丢弃 | 每编号每视图最多暂存两项；超过该编号限制的到达走既有逐笔验证，合法的当前投票或迟到进度投票仍可记入账本 |
| 同消息 BLS 回退绕过批量上限 | 批验签拒绝超过 10000 项后，回退逐笔验证全部项目；全部合法时还返回全部通过 | 回退入口也落实上限，超限全部拒绝，不做配对检查；覆盖 native 和 H2-v4 两套签名域 |
| QMDB 叶哈希只抽查三项 | 同长度操作集只核对首、中、尾项，其他位置不同的预计算哈希仍被使用，生成与实际写入内容不一致的根 | 缓存绑定到操作集的不可变版本身份。身份按需分配，移动与未修改的克隆可复用；追加、排序、合并及修改值缓冲区均使身份失效；其他操作集的哈希回退为正常计算 |
| 规范链通知携带不完整回滚集 | 延后合并失败或超时只记日志，随后通知携带不完整集合，订阅方无法得到正确的历史状态 | 通知构造要求完整集合。当前接口不可返回错误，失败时明确 panic，停止该调用路径；不把不完整数据作为正常通知发出 |

## 边界

本轮为 macOS 本地验证，未运行 Linux 节点、在线集群、长时间负载或生产部署。投票超出暂存限制时会增加逐笔验签工作；这是保留真实进度与限制暂存空间的取舍，不宣称恶意流量下的 CPU 使用已被全局限流。QMDB 身份匹配为常量时间，但尚未重跑 fleet 性能对照。
