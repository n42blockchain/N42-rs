## Durability ordering as implemented (entry-file mode, reviewer)

1. **Apply.** A block's entries go into the entry store's in-memory tail under the forest lock (`twig-core/src/qmdb_compat.rs:2457`, `entry_store.rs:524-608`); nothing reaches disk.
2. **Canonical follower.** `on_canonical` -> `persist_canonical` (`node_state.rs:3034`, `:3182`); one forest-lock hold moves the head and takes the per-block deltas (`:3204-3213`).
3. **Entry file sync.** `sync_entries_if_file` (`:3315`): tail written under the lock (`entry_store.rs:817`), `sync_data` on a dup'd handle outside it (`node_state.rs:3321`).
4. **Delta append.** `append_delta` (`:3863`): `set_len(from)`, a `[len u64][crc32][bincode]` record, `sync_data` (`:3890`); directory fsynced only when `from == 0` (`:3894`).
5. **Head roots.** `record_head_roots` (`:1711`) writes `forest.roots` in place, never fsynced (`:592-627`).
6. **Fold.** When `checkpoint_due`, `rewrite_checkpoint` (`:3329`): frontier via `write_durably`, rename `forest.log` -> `forest.log.sealed` (`:3359`), directory fsync (advisory). The compaction thread (`:3413`) hard-links the old `forest.ckpt` + sealed file into `recovery-archive/.pending-*`, fsyncs and renames it (`:2198-2232`); writes `forest.ckpt` by temp + fsync + rename + dir fsync (`:3743-3770`); unlinks the sealed file; retires archives below the MDBX `Finish` checkpoint (`:2161`, reader `bin/n42/src/main.rs:225`).
7. **MDBX commit.** `save_blocks` -> `run_with_qmdb_persisted` (`provider.rs:845`, `n42_persist.rs:207`) -> `on_state_persisted_checked` -> `settle_through` (`node_state.rs:3090`): waits until the delta log is durable through the batch's last block or fails the batch before the commit (with `IN_SCOPE=1` on its own thread, joined before the commit); then the read view advances, then MDBX commits.
8. **Restart.** `initialize(Finish head)` (`main.rs:271`) -> `initialize_file_mode` (`:2576`): checkpoint, or a fold archive if the checkpoint is ahead of the database; replay sealed then log, stopping at the DB head (CRC-framed, torn tail dropped, `:3913`); `from_entry_file` cuts the entry file to the cursor (`entry_store.rs:369-396`); `check_restored_root` against `forest.roots` (`:1726`).

## Checked and sound (reviewer)

- Log before MDBX: `settle_through` returns only after entries and then the delta through the batch's last block are fsynced; a refusal fails `save_blocks` before the commit in both orders (`n42_persist.rs:213-240`, `provider.rs:856-866`); on a QMDB chain the state-masking suffix is forced to 0.
- Entries are fsynced before the delta that names them; replay is CRC-32 framed with `checked_add` bounds; a rotation is durable no later than the next `append_delta(from=0)` directory fsync, which `settle_through` forces before any commit.
- Checkpoint, snapshot and frontier writes are temp + fsync + rename + dir fsync; archives built in `.pending-*`, fsynced, renamed; archived files are hard links of durable, never-rewritten files.
- Crash windows covered: fold between checkpoint rename and sealed unlink; heap rollback between snapshot write and log deletion; file-mode restore between entry cut and checkpoint write; genesis checkpoint; v1 -> entry-file adoption order.
- Archive selection: any candidate must replay exactly to `(number, hash)` and the restored root is still checked; retirement keeps label >= durable-1.
- Fail-stop: `poison_if_mutated`/`undo_failed` cover Store and Index failures in apply, leased apply, revert, re-apply; `move_to`, `insert`, `lease_tree`/`return_tree`, `set_canonical*`, `sync_entries`, `checkpoint`, `take_block_deltas` refuse once poisoned; a poisoned mutex poisons the forest; DuplicateKey detected before mutation.
- Read view vs truncation: `raise_floor` under the forest lock before release; `before_truncate` takes `advancing` and every reader slot; the cut counter invalidates a raised-but-not-advanced floor; journal published before the index changes; the shared mapping follows growth.
- bmt-core 256-bit depth guard; index shard errors instead of asserting; chain-state panic on an unfilled revert set is deliberate fail-stop.
