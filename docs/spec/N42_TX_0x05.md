# N42 Falcon-512 transaction v1

Status: opt-in implementation. No existing genesis or deployed fleet is changed.
This is padded Falcon-512, not a claim of final FN-DSA/FIPS 206 compliance.

## Wire and ownership

```
0x05 || RLP([chainId, nonce, tipCap, feeCap, gas, to, value, data,
             accessList, sigAlgo, pubKeyMode, publicKey, signature])
```

The signing digest is Keccak-256 of the same typed list without `signature`.
The transaction hash is Keccak-256 of the complete signed wire bytes.
The sender is the last 20 bytes of Keccak-256(publicKey), without an algorithm
prefix. This differs from the separate 0x50 Ed25519 account derivation.

- `sigAlgo = 0`, `pubKeyMode = 0`; no key references or registry lookup.
- Public key: 897 bytes. Signature: fixed 666-byte padded Falcon-512.
- Chain ID: positive uint64; nonce and gas: uint64; fee caps: uint128;
  value: uint256. Tip cannot exceed the fee cap.
- Recipient: a required 20-byte address. Creation is not supported.
- Data and access lists are committed to the signature. The first wallet UI
  supports native transfers with empty data and access list only.
- Local verification is mandatory even on claimed/attested sender ingestion
  paths. Ed25519 batch results do not authorize Falcon transactions.

The public fixtures in `crates/n42/tx-types/tests/testdata` were produced by
independent Go and wallet signers. They contain no private keys. Never fund
fixture accounts; they are test artifacts.

## Activation and RPC

Rust: an isolated new genesis must explicitly set `config.pqTx: true`.
Absent or false leaves admission and block validation disabled. This is a
chain configuration change, not a command-line bypass. Do not change an
existing network's genesis in place. A coordinated upgrade/fork design is
required before enabling an existing deployed network.

Go compatibility branch: `config.pqTxBlock` activates at the agreed canonical
block, no earlier than London. Absent leaves it disabled. All validators
must share the configuration and implementation before activation.

`n42_getPQCapabilities` returns:

```json
{"protocol":"n42-pq-v1","transactionType":"0x05","algorithm":"Falcon-512",
 "signatureEncoding":"padded-666","publicKeyMode":0,"chainId":"0x5e",
 "enabled":false}
```

Wallets require this exact protocol and chain ID, plus `enabled: true`, before
broadcast. Decoding support alone is not an activation signal. The Rust method is added to configured transports. Restrict those endpoints
using the node/proxy access policy; do not add an unknown `n42` name to
`--http.api`. The Go node uses its existing `n42` namespace.

## Operator handoff

1. Build and test this branch. Retain the prior binary and a stopped-node
   database/config backup. Verify all seven nodes use the same genesis.
2. Use a separate data directory and an explicitly enabled private genesis.
   Fund a newly generated Falcon address with test funds, after its encrypted
   backup has been restored and checked. Existing EVM seeds do not derive it.
3. Check capabilities, chain ID, pending nonce, balance and fee cap. Submit
   through `eth_sendRawTransaction`; compare the returned hash to local
   Keccak-256 of the wire bytes.
4. Check receipt type 0x05, canonical block hash, balance and nonce on all
   nodes, restart/import, invalid-signature rejection and disabled-chain
   rejection. Retain RPC responses without keys or backup passwords.
5. Unknown submission outcomes remain pending. Query the original hash;
   never send a replacement payment merely because an RPC timed out.

The recent seven-node deployment has not been upgraded by this change.
Access to its confirmed host and an operator-coordinated activation remain
external acceptance steps. Mainnet transactions and device QA are not
implied by local tests.

## Legacy Go compatibility boundary

The old Go Falcon module used a demonstrator verifier. The compatibility branch
replaces it with an actual Falcon verifier. This also changes Falcon precompile
results: old demonstration signatures are deliberately invalid. Before upgrading
an existing Go chain, audit historical use of that precompile and PQ transaction
paths. Do not replay a chain that relied on demonstrator results under silently
changed consensus rules. Use a separate test chain or an explicitly reviewed,
coordinated fork with historical verification rules retained as required.

Read-only fleet preflight (repeat `--rpc` for all confirmed endpoints):

```sh
python3 scripts/pq/check_falcon_rpc.py --chain-id 94 \
  --rpc https://node1.example --rpc https://node2.example
```

The probe requires compatible enabled capabilities and compares all nodes at
one common height. It never signs or broadcasts. A successful probe does not
replace transfer, restart, reorg or recovery acceptance.

## Local verification, 2026-10-30

- `cargo test -p n42-tx-types --test falcon`: 3 passed. Wallet/PQClean and
  Go signers' public vectors verify, hash and roundtrip through wire, pooled,
  compact storage and JSON forms. EVM mapping and 0x05 receipt JSON also pass.
- `cargo test -p n42-testing test_falcon_transfer__is_mined_and_typed_0x05`:
  1 passed. The RPC handler rejects a corrupted signature, admits a correct raw
  transaction, builds/imports a block, and stores a successful 0x05 receipt.
  Recipient balance, sender nonce and exact value plus effective gas charge
  match the expected state.
- `cargo test -p n42-tx-ingest falcon_gate_and_signature_cannot_be_bypassed --lib`:
  1 passed across 16 enabled/attested/sharded/corrupted-signature combinations.
  Disabled or invalid Falcon transactions are dropped; external sender claims
  cannot replace the cryptographically verified account.
- `cargo clippy --no-deps -p n42-tx-types -p n42-engine-types -p n42-tx-ingest
  -p n42 --lib --bins -- -D warnings`: passed for selected packages. Existing
  upstream dependency warnings remain outside this check.
- Read-only probe: enabled/matching mock nodes pass; disabled and divergent
  nodes fail. The public `https://rpc.n42.world` endpoint currently returns
  `-32601` for `n42_getPQCapabilities`, so the wallet fails closed there.

These results are local source/build acceptance. Seven-node deployment,
operator activation, restart/reorg checks and real-device QA remain separate.
